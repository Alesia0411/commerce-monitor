# 项目原型使用与实现说明

本版本将单商品场景演示扩展为多商品运营原型。保留现有数据和 API，新增 `/api/v1` 业务接口以及 `/api/auth` 账号接口。论文来源只在技术文档 PAPERS.md 中说明，不展示在产品界面。

## 1. 功能范围

| 模块 | 已实现的操作 |
|---|---|
| 登录与权限 | 自动生成初始管理员、PBKDF2 密码哈希、8 小时会话、退出、管理员创建成员、只读/操作员/审核员/管理员角色 |
| 商品档案 | 自有/竞品登记、规格、价格、成本、描述、促销、评价样本、授权确认、编辑版本冲突检查、搜索、归档 |
| 数据导入 | JSON 数组导入、每批 200 条上限、金额校验、重复商品检查、逐行成功/失败结果 |
| 商品时间线 | 每商品独立快照、运行历史、变更建议；不会将两个商品互相比成涨跌 |
| 定时监控 | 每商品间隔设置、启停、到期时间持久化；检查的是当前录入数据，不是实时淘宝页面 |
| 后台任务 | SQL 持久队列、入队输入冻结、幂等请求、状态查询、取消待执行任务、失败重试 |
| 竞品对比 | 自有商品与竞品关联、同规格校验、相同促销条件才计算价差 |
| 运营建议 | 按标题/描述/促销/评价/价格变化生成草稿；可选真实模型；审核与证据撤销 |
| 执行任务 | 批准建议转运营/美工任务、负责人、截止日、执行记录、状态流转、证据失效时阻止推进 |
| 知识与经验 | 知识录入形成候选、校验/审核/停用、批准知识用于后续检索 |
| 反馈与报告 | 建议评分、文字反馈、完成/批准统计、Markdown 报告下载、审计记录 |
| 风控与评测 | 保留异常暂停、配额、去重、隔离安全场景及交接检查 |

这是功能闭环原型，不等于已完成 v1.1 全部生产能力。真实平台授权接入、分布式部署和完整论文复现依然不在已验证能力中。

## 2. 启动和账号

```powershell
cd commerce-monitor
python run.py
```

首次启动会在项目根目录生成 `.local-credentials.json`，包含租户 a/b 的管理员账号。该文件已被 Git 和 Docker 构建忽略；不要上传或分享。界面选择对应租户并使用该账号登录。每个账号只访问所属租户。

推荐使用 Python 3.12：

```powershell
python run.py
```

默认地址 http://127.0.0.1:8000，可通过环境变量 PORT 调整端口。

管理员可以通过 `/docs` 中 `POST /api/auth/members` 创建成员。请求头传登录返回的 Bearer token，正文为 username、password、role。角色可选 admin、operator、reviewer、viewer。审核、证据撤销、来源恢复要求审核员或管理员；viewer 只允许读取。所有业务写入还会校验租户与对象归属。

旧固定演示 token 默认禁用；仅测试兼容时设置 `ALLOW_LEGACY_TOKENS=1`。不要在正式试用中启用它。当前是本地账号系统，不包含企业单点登录、密码找回、账号停用和细粒度权限矩阵。

## 3. 完整操作流程

1. 登录后，在“商品与竞品”登记至少一件自有商品和一件同规格竞品，勾选数据使用授权。
2. 对商品点击“监控一次”，在后台任务页确认 BASELINE，形成第一份快照。
3. 编辑其中一件商品的价格、描述或促销，再运行一次监控；后台任务生成变化建议。
4. 在“竞品对比”关联同规格商品。促销条件不同则不给出误导性价差。
5. 在“运营建议”查看证据并批准，然后在“执行工作台”创建运营或美工任务。
6. 将任务从 TODO 推进为 DOING，再记录结果并完成。若证据被撤销，任务不能继续推进。
7. 在“知识库与反馈”给建议评分、补充执行反馈并导出报告。
8. 对批准建议归纳工作流候选，在经验页校验并批准，用于之后的分析。
9. 对需持续检查的商品设置监控间隔并启用计划。页面每 5 秒刷新；编辑输入时暂停自动刷新，避免覆盖输入。

JSON 导入示例：

```json
[
  {"title":"品牌A保温杯","item_id":"own-001","sku":"500ml-1","role":"own","price":"109.00","cost":"60.00","description":"可拆洗杯盖","authorized":true},
  {"title":"品牌B保温杯","item_id":"comp-001","sku":"500ml-1","role":"competitor","price":"99.00","description":"轻量杯身","authorized":true}
]
```

导入是逐行处理，不承诺整批事务原子性；界面明确显示成功数和失败行。

## 4. 模块增量

- `app/prototype.py`：商品、计划、持久任务、竞品关联、执行任务、反馈、知识录入和报告的应用服务/API。
- `app/access.py`：密码哈希、账号、过期会话与登录接口。
- `web/workspace.js`：业务表单与操作方法，与原有 Vue 外壳分离。
- `app/service.py`：新增输入商品和商品标识，快照按商品隔离。
- `app/main.py`：组装新路由、后台轮询 Worker、访问控制中间件。
- `tests/test_prototype.py`、`tests/test_access.py`：新增持久任务、输入冻结、权限和登录测试；HTTP 测试扩展完整任务闭环。

复用现有 SQL Store，新增 product、plan、job、pair、task、feedback、knowledge、member、session 等记录类型，不破坏旧快照。MySQL/SQLite 共用 SQLAlchemy 适配；Redis 仍用于配额。

后台每 2 秒扫描到期计划与待处理任务，每租户每轮最多处理 2 项。计划以“计划 ID + 到期时间”去重，任务以“job ID”绑定运行；入队时冻结商品版本，避免编辑后的数据混入旧任务。重启将遗留 RUNNING 作业标为失败供人员确认重试，不声称支持任意节点精确续跑。

## 5. 原型约束与生产化工作

- 单进程 Worker 加进程锁；禁止多实例/多 Worker 部署。尚未实现分布式租约、Redis Streams、Outbox 和故障时跨记录原子性。
- 商品数据来源为授权人工录入与合成数据；没有真实淘宝/服务商采集适配器。授权确认不是自动证明来源合法。
- 商品对比基于录入价格及条件相等，不是复杂优惠解析或个性化到手价。
- 离线模型使用规则模板；配置真实模型后支持结构化建议，但尚未完成真实模型质量、成本及并发压测。
- RAG 为受权限过滤的轻量检索，无向量索引；知识审核复用记忆生命周期。
- “美工任务”是需求草稿，不自动生成图像或发布素材；反馈评分不等于转化或利润因果评估。
- MySQL/Redis Compose 需在部署环境实测；原型数据库迁移应在生产化时改用专用表和 Alembic。
- 密钥、登录暴力防护、角色体系、日志保留与数据删除需要生产安全审查；本地初始凭据文件应限制操作系统访问权限。

## 7. 根据自有商品搜索并关联竞品

保留手动登记，并新增两个入口：“商品与竞品”列表中的“发现竞品”，以及“竞品对比”页中的搜索面板。

1. 选择已登记且有效的自有商品，系统自动读取标题、类目与规格。
2. 搜索本租户已登记竞品和授权导入商品库，展示匹配分与匹配原因。
3. 选择候选关联，或勾选“自动关联高匹配候选”后搜索。
4. 来自商品库的候选在关联时登记为竞品；已有商品直接复用，关联去重。关联不会自动启用监控计划。

当前搜索来源为本地授权数据，不是淘宝在线搜索。候选库可以通过“授权商品库导入”导入服务商合法导出数据；没有数据时返回空结果，不编造商品。合成数据始终单独标注。真实在线搜索须另行接入具有相应权限的官方接口或服务商。

新增模块 `app/discovery.py`：`CatalogProvider` 为搜索适配器接口，`LocalCatalogProvider` 负责租户过滤和候选去重，`Discovery` 负责评分、搜索记录、登记与关联。当前匹配为确定性规则，不宣称使用大模型语义搜索。

评分：标题字符二元组 Jaccard 相似度 ×55 + 规格一致 30 + 非“通用”同类目 15。自动关联要求同规格、明确同类目、标题相似度至少 45%、总分至少 70。该分值用于排序，不是置信概率。规格不同只能查看，不允许关联；促销条件是否可比仍由竞品对比模块独立判断。

搜索记录保存自有商品与候选版本，30 分钟过期；关联前重查授权、归档状态、版本和租户归属。过期或修改后的结果需重新搜索。接口：

- `POST /api/v1/discovery/search`：own_id、auto_link、limit。
- `POST /api/v1/discovery/{id}/link`：candidate_ids，必须来自该次搜索。
- `POST /api/v1/discovery/catalog/import`：products 数组，最多 500 条，逐行报告。

新增测试覆盖自动登记/关联、重复请求去重、空库、跨租户、规格不符、结果过期版本和人工选择。相关验证请运行 README 中的检查命令。
